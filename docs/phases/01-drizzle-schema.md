# Phase 1 — Drizzle over the live schema

Source: `docs/reference/tessera-roadmap.md`, Phase 1. Adapted per `docs/decisions.md`
D-3 (local Postgres before Neon) and D-7/D-8 (this phase's own findings).

## Delivers

Typed database access to the local Postgres database, and a check that screams if the
live schema and `tessera-schema.sql` ever diverge.

## What was built

- **Local database provisioned** (D-7): since the Windows-service PostgreSQL install had
  no known superuser password and this session has no admin rights to reset it, a second,
  user-owned cluster was initialized with `initdb` at `.pgdata/` and started on port 5433
  via `npm run db:start` (wired into `npm start`/`npm run dev`'s `prestart`/`predev`
  hooks, so it's automatic going forward). `tessera-schema.sql` was applied to it once,
  directly, exactly as it will be applied to Neon later.
- **`backend/drizzle.config.ts`** — introspection-only config. `drizzle-kit pull`'s
  journal/snapshot output is redirected to a gitignored `backend/.drizzle-introspect/`
  scratch directory (see D-8 — it can't be turned off entirely, contrary to what the
  roadmap assumed); `backend/src/db/schema.ts` and `relations.ts` are the two files
  actually copied from there into the app.
- **`backend/src/db/schema.ts`** — generated by `npx drizzle-kit pull`, then hand-fixed
  in two places the generator got wrong:
  - `"user".email` (a `citext` column) was emitted as a broken `unknown("email")` call
    referencing a function that isn't even imported — replaced with a proper
    `customType` definition for `citext`.
  - The `class` table was emitted as `export const class = ...`, which doesn't parse —
    `class` is a reserved word. Renamed the exported binding to `schoolClass`; the
    underlying SQL table name is still `"class"`, and the `class:` relation key
    (in `with: { class: true }` queries) is unchanged.
- **`backend/src/db/relations.ts`** — generated by the same `pull`, declaring exactly the
  joins the roadmap calls for (`student → user`, `enrollment → student, class`,
  `teaching_assignment → teacher, class, subject`, `mark → assessment, student`,
  `mark → mark` for `supersedes_mark_id`), updated for the `schoolClass` rename above.
- **`backend/src/db/client.ts`** — a `pg.Pool` wrapped by `drizzle()`. SSL is on
  conditionally: off for `localhost`/`127.0.0.1` connection strings, `{ rejectUnauthorized:
  true }` otherwise — so the same code works unchanged once `DATABASE_URL` points at Neon.
- **`backend/src/db/pg-errors.ts`** — maps Postgres errors to API error codes in two
  layers: known constraint names get the specific code the roadmap names
  (`one_current_mark` → `MARK_ALREADY_CURRENT` 409, `reason_required_when_superseding` →
  `MARK_REASON_REQUIRED` 422, `user_email_key` → `USER_EMAIL_TAKEN` 409), everything else
  falls back to a generic code by SQLSTATE (unique/check/not-null/invalid-input →
  `CONFLICT`/`VALIDATION_FAILED`; foreign-key violation → `NOT_FOUND`, since a dangling
  client-supplied reference isn't a server error). Later modules add their own constraint
  entries here as they're built.
- **`scripts/schema-check.mjs`** (root-level, per the repo shape in `docs/00-overview.md`)
  — read-only, asserts table count, all 11 enum value sets, the two `mark` check
  constraints, the `one_current_mark` partial unique index (printing its actual
  predicate), the three nullable EMIS columns, and `"user".email` being `citext`.
- **`scripts/verify-constraints.sql`** — a repeatable, transaction-rolled-back script
  that proves `one_current_mark` and `reason_required_when_superseding` actually reject
  bad inserts, by inserting real (then discarded) rows.
- **`backend/src/db/verify-relational-query.ts`** — a repeatable check that a nested
  relational query (`assessment` with `class`/`subject`/`term`/`teacher`/`marks`) is one
  round trip, by counting calls through the pool.
- **`GET /api/health`** extended to report `db: { reachable, serverVersion, latencyMs }`
  — this was actually a Phase 0 "Done when" item in the original roadmap, which assumed a
  database already existed even in Phase 0 (C1); under D-3 it naturally lands here
  instead, once a database exists to report on.
- Two factual corrections made to `docs/reference/tessera-roadmap.md` itself, annotated
  in place (D-8): the real table count is 22, not 24; and `drizzle-kit pull` always needs
  an `out` path, contrary to what the roadmap's Phase 1 text assumed.

## Done when — verified

- [x] `node scripts/schema-check.mjs` prints one `OK` line per assertion (22 tables, all
      11 enums with exact value sets, both check constraints, the `one_current_mark`
      index with its predicate printed verbatim as
      `WHERE (state = ANY (ARRAY['draft'::mark_state, 'published'::mark_state]))`, the
      three nullable EMIS columns, `"user".email` as `citext`) and exits 0.
- [x] `scripts/verify-constraints.sql`, run by hand against the real database inside a
      rolled-back transaction, proves both constraints reject bad inserts:
      `duplicate key value violates unique constraint "one_current_mark"` and
      `new row for relation "mark" violates check constraint
      "reason_required_when_superseding"`. No test data persisted (verified by count
      queries returning 0 afterward).
- [x] No migration commands anywhere in the repo — `node scripts/guard-no-migrations.mjs`
      exits 0 after this phase's changes too (it initially flagged its own explanatory
      comments in `drizzle.config.ts` for containing the literal phrase "drizzle-kit
      push"; reworded, not suppressed).
- [x] A nested relational query (`db.query.assessment.findMany({ with: {...} })`) is
      proven to be a single round trip via `backend/src/db/verify-relational-query.ts`.
- [x] `npm start` still brings up both services; `GET /api/health` through the proxy now
      reports `db.reachable: true`, a real Postgres version string, and steady-state
      latency of ~1ms (well under the roadmap's 200ms budget — the first request after a
      cold pool was ~287ms, which is connection setup, not query time).
- [x] One commit for this phase.
